Customer Map Planner

Excel 거래처 목록을 지도 작업으로 바꾸는 과정에서 반복되는 주소 검색, 근접 거래처 파악, 라벨 정리와 인쇄 준비를 하나의 브라우저 워크플로로 묶었습니다.

Live Demo ↗Source ↗CI ↗
InputExcel / built-in sample
MapKakao Maps + Geocoding
AlgorithmHaversine + connected clustering
OutputExcel + A4 landscape print

문제 정의

01

Excel과 지도 사이의 반복 작업

거래처 주소를 하나씩 검색하고 필요한 곳만 다시 추려내는 과정이 반복됩니다.

02

거리만 가까워도 한눈에 보기 어렵다

같은 권역의 거래처라도 마커와 라벨이 겹치면 실제 현장 판단에 쓰기 어렵습니다.

03

최종 산출물은 화면이 아니라 인쇄물

현장에서 볼 수 있는 A4 가로 지도가 필요해 화면 렌더링과 print layout을 함께 설계했습니다.

완성도를 높이기 위해 추가한 것

UX

실패주소 복구

지오코딩 실패를 숫자로만 보여주지 않고 실패 목록에서 주소를 수정하고 개별/전체 재시도할 수 있게 했습니다.

PERF

Batch + cache

선택 주소를 작은 batch로 처리하고 동일 주소는 메모리 cache를 사용해 반복 API 호출을 줄입니다.

LAYOUT

Responsive relayout

화면 크기가 바뀌면 Kakao map을 relayout하고 전체 bounds 및 라벨 위치를 다시 계산합니다.

DATA

Round-trip workflow

입력 샘플 Excel을 제공하고, 선택한 거래처 목록도 다시 Excel로 내보낼 수 있습니다.

PRIVACY

브라우저 경계

Excel/customer data는 서버에 저장하지 않고 선택 주소만 geocoding API에 전달합니다. API key도 저장하지 않습니다.

PRINT

화면과 인쇄 분리

화면은 반응형 작업공간으로, 인쇄 시에는 297×210mm 지도로 강제해 업무 산출물 형태를 보장합니다.

핵심 알고리즘

두 좌표 사이 거리는 Haversine 공식을 사용하고, 각 지점을 첫 기준점과만 비교하지 않습니다. threshold 이내로 이어지는 점을 BFS 방식으로 탐색해 transitive proximity를 하나의 cluster로 묶습니다.

distanceMeters(A, B) ↓ A ↔ B <= threshold B ↔ C <= threshold ↓ cluster = [A, B, C] ※ A ↔ C가 직접 threshold를 넘더라도 연결요소라면 같은 그룹

검증

Pure utility tests

거리 계산, threshold 정규화, 거래처 identity/search, clustering을 Node test runner로 검증합니다.

Syntax gate

`node --check`로 browser script의 문법 오류를 CI에서 차단합니다.

Deployment evidence

GitHub Pages 배포까지 자동화되어 실제 브라우저에서 결과를 확인할 수 있습니다.

왜 CRUD API에서 더 확장했는가

01

API만 있으면 사용 흐름이 보이지 않는다

검토자가 curl을 직접 작성하지 않아도 검색·등록·수정·삭제와 오류 처리를 체험할 수 있도록 작은 management console을 함께 제공합니다.

02

H2 통과만으로 MySQL 호환을 증명하기 어렵다

기본 실행은 H2로 가볍게 유지하면서 Testcontainers에서 실제 MySQL 8.4를 띄워 Mapper SQL을 검증합니다.

03

실행 가능성도 품질의 일부다

Dockerfile과 Compose를 제공하고 CI에서 image build까지 실행해 “코드는 있지만 실행이 안 되는” 상태를 차단합니다.

제품 표면

UI

Browser management console

검색어, 이메일 도메인, 정렬, 페이지 크기를 조절하고 사용자 등록·수정·삭제를 API에 직접 연결합니다.

DOC

OpenAPI / Swagger

API 계약을 자동 문서화해 UI에서 다루지 않는 endpoint와 request/response도 검토할 수 있습니다.

OPS

Actuator health

컨테이너와 운영 확인을 위해 최소 health/info endpoint만 노출합니다.

DATA

Excel export

현재 검색 조건을 사용해 사용자를 XLSX로 내려받을 수 있도록 문서 생성 책임을 별도 service에 둡니다.

DB

Dual runtime

설치 없는 H2 경로와 실제 MySQL profile을 분리해 빠른 검토와 실환경 SQL 검증을 동시에 지원합니다.

CONTAINER

Docker Compose

MySQL health 이후 애플리케이션을 시작하고 `/actuator/health`로 앱 상태까지 확인합니다.

HTTP 오류 계약

400 VALIDATION_ERROR → request body validation 400 INVALID_QUERY → page / size / sort / direction validation 404 USER_NOT_FOUND → unknown user id 409 DATA_CONFLICT → duplicated email { "code": "VALIDATION_ERROR", "message": "Request validation failed", "timestamp": "...", "fieldErrors": { "email": "..." } }
정렬 컬럼은 요청 문자열을 SQL `${...}`에 그대로 삽입하지 않습니다. Service whitelist와 MyBatis ``가 허용된 DB column만 선택합니다.

검증 구조

MockMvc integration

UI 제공, health, 조회, 검색, 등록, 수정, 삭제, validation, conflict, pagination, Excel, OpenAPI를 애플리케이션 context에서 검증합니다.

Testcontainers MySQL

실제 MySQL container에서 pagination과 createdAt 정렬 query가 정상 작동하는지 확인합니다.

Container build gate

GitHub Actions에서 Maven verify와 Docker image build를 별도 job으로 수행합니다.

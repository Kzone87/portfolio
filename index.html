SERVICES

이런 개발을 맡을 수 있습니다.

기능 목록부터 받는 방식보다 현재 업무가 어떻게 돌아가는지 확인한 뒤 필요한 범위를 정리합니다.

01

업무용 웹 시스템 · 관리자 기능

엑셀이나 메신저로 흩어진 업무를 한 화면에서 조회·등록·수정·처리하도록 구성합니다.

  • 거래처 / 회원 / 주문 / 신청 데이터 관리
  • 검색 · 필터 · 페이지네이션 · 상태 처리
  • 운영자용 관리 화면과 업무 흐름 설계
02

Excel · 반복 업무 자동화

기존 Excel 데이터를 버리지 않고 웹 업무와 연결하거나 반복 작업을 줄이는 도구를 만듭니다.

  • XLSX / CSV 입력 검증 및 가공
  • 검색 결과 Excel 다운로드
  • 주소 · 지도 · 보고서 · 출력 자동화
03

REST API · 데이터 연동

프런트엔드나 다른 서비스가 안정적으로 사용할 수 있는 API와 데이터 경계를 구성합니다.

  • CRUD · 검색 · 정렬 · 페이지네이션
  • Validation · 오류 응답 계약 · API 문서
  • 외부 API와 내부 데이터 연결
04

기존 웹서비스 개선 · 유지보수

이미 운영 중이거나 과거에 만든 웹 프로젝트의 문제를 분석하고 필요한 범위부터 정리합니다.

  • 버그 수정 · 기능 추가 · 코드 구조 개선
  • 환경변수 / credential 정리
  • 레거시 코드의 단계적 현대화

PROCESS

개발보다 먼저 범위를 명확히 합니다.

외주에서 가장 큰 문제는 코드보다 요구사항이 계속 바뀌는 것입니다. 시작 전에 완료 기준부터 맞춥니다.

  1. 01

    업무 확인

    현재 사용 방식, 불편한 지점, 입력·출력 데이터를 확인합니다.

  2. 02

    범위 확정

    필수 기능과 제외 범위, 완료 조건을 문서로 정리합니다.

  3. 03

    구현 · 검증

    핵심 흐름부터 구현하고 예외 상황과 데이터 처리까지 검증합니다.

  4. 04

    검수 · 수정

    확정된 범위를 기준으로 실제 사용 흐름을 점검하고 수정합니다.

  5. 05

    납품 · 인수인계

    소스, 실행/배포 방법, 필요한 설정과 운영 주의사항을 전달합니다.

DELIVERY STANDARD

납품할 때 남기는 것

01

범위가 보이는 소스

기능별 책임을 구분하고 유지보수 가능한 구조를 우선합니다.

02

Git 변경 이력

수정 범위와 변경 이유를 추적할 수 있도록 버전 관리를 사용합니다.

03

검증 수단

프로젝트 성격에 따라 자동화 테스트, CI 또는 재현 가능한 확인 절차를 둡니다.

04

실행 · 배포 문서

환경설정, 실행 방법, 필요한 외부 서비스와 운영상 주의사항을 정리합니다.

05

Secret 분리

API key와 credential은 소스에 직접 포함하지 않는 것을 기본 원칙으로 합니다.

06

완료 기준 확인

“대충 동작”이 아니라 합의한 사용자 흐름을 기준으로 검수합니다.

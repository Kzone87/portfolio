SERVICES

외주에서 바로 연결할 수 있는 개발 범위

기술 스택을 먼저 정하기보다 현재 업무와 완료 조건을 확인한 뒤 필요한 범위를 설계합니다.

01

업무용 웹 시스템

고객·거래처, 신청, 업무 건을 검색하고 등록·수정하며 역할과 상태를 관리하는 시스템을 구성합니다.

  • 관리자 Dashboard
  • CRUD · 검색 · 필터
  • RBAC · 상태 전이 · Audit
02

Excel · CSV 자동화

반복해서 정리하는 파일 업무를 브라우저 도구나 내부 시스템으로 전환합니다.

  • Import · Validation
  • 정규화 · Rule Builder
  • Column Mapping · Export
03

REST API · 시스템 연동

프런트엔드와 외부 시스템이 안정적으로 사용할 데이터 경계, 상태, 실패 처리 기준을 구현합니다.

  • Spring Boot · MyBatis
  • HTTP 오류 계약
  • Sync job · retry model
04

기존 서비스 개선

전체 재개발보다 현재 문제의 영향 범위를 확인하고 가장 작은 안전한 변경 단위부터 개선합니다.

  • Bug fix · 기능 추가
  • Credential 정리
  • Legacy modernization

PROCESS

기능 수보다 완료 조건을 먼저 맞춥니다.

외주 실패의 원인이 되기 쉬운 요구사항 변경을 줄이기 위해 입력·출력·권한·상태·제외 범위를 먼저 정리합니다.

  1. 01

    업무 확인

    현재 사람·데이터·도구가 어떻게 연결되는지 확인합니다.

  2. 02

    범위 확정

    필수 기능, 제외 기능, 완료 조건을 문서화합니다.

  3. 03

    핵심 흐름 구현

    Happy Path뿐 아니라 validation과 오류 상태까지 구현합니다.

  4. 04

    검증

    테스트, CI 또는 재현 가능한 검수 절차로 기능을 확인합니다.

  5. 05

    납품

    소스와 실행·배포 방법, 환경설정과 운영 주의사항을 전달합니다.

DELIVERY STANDARD

코드만 넘기지 않습니다.

01

변경 이력

Git으로 변경 범위와 이유를 추적할 수 있게 합니다.

02

Validation

잘못된 입력과 예외 상황을 정상 기능의 일부로 다룹니다.

03

검증 수단

자동화 테스트·CI 또는 재현 가능한 검수 절차를 둡니다.

04

Secret 분리

API Key와 credential을 소스 코드에 직접 넣지 않습니다.

05

실행 문서

로컬 실행, 빌드, 필요한 설정과 외부 서비스를 정리합니다.

06

범위 기준 검수

합의된 사용자 흐름과 완료 조건을 기준으로 납품합니다.

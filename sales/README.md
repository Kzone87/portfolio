# Marketplace Sales Kit

공개 포트폴리오를 실제 외주 수주와 반복 매출로 연결하기 위한 내부 판매 문서 모음입니다.

## 1. 판매상품 마스터

[`PRODUCT-CATALOG.md`](./PRODUCT-CATALOG.md)

크몽·숨고 등 수주 플랫폼에서 실제로 판매할 상품은 아래 10개로 고정합니다.

1. 기존 웹사이트 기능 추가
2. Excel·CSV 반복작업 자동화
3. 고객·직원·업무 관리자페이지
4. 외부 API 데이터 연동
5. PDF·이미지 문서 값 추출
6. 기존 서비스 AI 요약·분류·초안 기능 추가
7. 쇼핑몰 주문·배송·환불 관리자페이지
8. 예약·기사배정·현장업무 관리
9. 공개 웹데이터 수집·Excel 정리
10. 기존 웹서비스 오류수정·기능개선·유지보수

상품명은 기술명이 아니라 **고객이 검색하는 작업명**을 사용합니다. 각 상품의 초기 패키지 가격, 고객 입력자료, 납품 결과, 완료 기준, 공개 포트폴리오 증거는 마스터 카탈로그를 기준으로 합니다.

## 2. 크몽 등록 원고

[`KMONG-LISTINGS.md`](./KMONG-LISTINGS.md)

기존 장문 원고는 관리자페이지 / Excel·CSV / REST API 상품의 상세 설명 소스로 유지합니다. 신규 상품 등록 시 제목과 패키지 구조는 `PRODUCT-CATALOG.md`를 우선 적용하고, 이 문서의 범위·FAQ 표현을 필요한 만큼 재사용합니다.

AI 상품은 별도 [`AI-WORKFLOW-SALES.md`](./AI-WORKFLOW-SALES.md)를 사용합니다.

## 3. AI 상품

[`AI-WORKFLOW-SALES.md`](./AI-WORKFLOW-SALES.md)

- AI 기능추가 상품 원고
- 플랫폼용 패키지 가격
- 숨고 맞춤견적 응답
- 포트폴리오 이미지 순서
- 60초 영상 구성
- provider 비용 / RAG / 신규 Workflow 범위 분리
- Human Review / Structured Output / Audit 증거

공개 증거는 `AI Workflow Review Desk V2`를 사용합니다.

## 4. 숨고 견적 응답

[`SOOMGO-QUOTES.md`](./SOOMGO-QUOTES.md)

고객 요청서에 따라 사용할 응답 템플릿을 보관합니다. 상품 선택은 `PRODUCT-CATALOG.md`의 10개 작업 중 가장 가까운 항목을 먼저 고르고, 고객의 현재 방식·원하는 결과·예산·일정을 확인한 뒤 범위를 줄이거나 확장합니다.

## 5. 포트폴리오 이미지/영상

[`PORTFOLIO-ASSETS.md`](./PORTFOLIO-ASSETS.md)

대표 프로젝트별로:

- 대표 이미지 문구
- 스크린샷 순서
- 이미지별 고객 중심 캡션
- 60초 영상 흐름
- 개인정보/민감정보 체크

를 정리했습니다.

## 6. 가격/범위 방어

[`SCOPE-RULES.md`](./SCOPE-RULES.md)

견적 시 반드시 분리할 것:

- 포함 / 제외
- 수정 / 기능추가
- 외부 서비스 비용 / 개발비
- 결함수정 / 유지보수 / 신규기능
- 단계별 개발
- 완료 조건

가격을 낮추면 범위도 같이 줄입니다.

## 7. 유지보수 / 운영지원 Retainer

[`MAINTENANCE.md`](./MAINTENANCE.md)

납품 후 또는 기존 시스템 인수 후 월 운영지원 기준:

| 플랜 | 월 비용 | 포함시간 | 대응 시작 기준 |
| --- | ---: | ---: | --- |
| CARE | 15만원 | 1시간 | 영업일 2일 이내 |
| OPS | 30만원 | 3시간 | 영업일 1일 이내 |
| PRIORITY | 50만원 | 5시간 | 영업일 기준 당일 |

신규 기능, 24/7 on-call, 휴일/야간 대응, 외부 서비스 이용료는 기본 월 상품과 분리합니다.

## 8. 견적서 / 범위확정

[`QUOTE-TEMPLATE.md`](./QUOTE-TEMPLATE.md)

상담 후 실제 견적을 보낼 때 다음을 한 문서에서 확정합니다.

- 현재 문제와 완료 목표
- 포함 기능 / 제외 기능
- 사용자와 권한
- 상태 흐름과 외부 연동
- AI 사용 시 output/human approval 경계
- 검증·납품 기준
- 개발 금액과 일정
- 수정과 신규 기능 추가의 구분
- 외부 서비스 비용
- 납품 후 유지보수/운영지원 옵션

금액만 먼저 보내지 않고 **범위와 완료 조건을 먼저 고정한 뒤 견적**하는 것을 기본 원칙으로 합니다.

## 운영 원칙

- 포트폴리오는 구현 능력 증명용입니다. 문의·견적·결제·계약은 수주 플랫폼에서 진행합니다.
- 고객에게는 기술명이 아니라 현재 수작업과 원하는 결과를 묻습니다.
- 기능 개수보다 업무 복잡도와 기존 코드 상태로 견적합니다.
- AI/API/OCR provider 사용료는 개발비와 분리합니다.
- 신규 기능과 유지보수를 구분합니다.
- 공개 포트폴리오에는 공개 저장소와 가상 데이터만 사용합니다.
- 비공개 사업 프로젝트는 판매 증거로 사용하지 않습니다.

# 숨고 견적 응답 템플릿

숨고는 고객 요청 내용을 보고 맞춤 견적을 보내는 방식이므로, 고정 패키지 설명보다 **고객 요청을 다시 요약하고 범위·예산·다음 확인사항을 짧게 제시하는 답변**이 중요합니다.

아래 문구는 복사 후 실제 요청 내용에 맞게 수정하는 초안입니다.

---

# 1. 관리자페이지 / 업무관리 시스템

## 첫 응답 템플릿

안녕하세요. 요청하신 내용은 단순 홈페이지보다 **업무용 관리자 시스템**에 가까워 보입니다.

현재 설명 기준으로는 다음 범위를 우선 확인하면 정확한 견적을 낼 수 있습니다.

- 관리할 데이터: 고객 / 거래처 / 신청 / 주문 / 업무 등
- 사용하는 사람: 관리자 / 직원 / 고객 여부
- 필요한 기능: 등록 / 수정 / 검색 / 상태변경 / Excel 등
- 업무 상태: 접수 → 진행 → 완료처럼 정해진 순서가 있는지
- 기존 소스 / DB / 서버 유무

비슷한 공개 구현 사례로는 `Business Ops Dashboard V6`가 있으며 고객-업무 관계, 권한, 상태 처리, 변경 이력, 우선순위/마감일을 구현해 두었습니다.

현재 범위가 **관리자 CRUD 중심이면 150만원 전후부터**, 고객/업무/권한/DB/API가 함께 들어가면 **300만원 이상 범위**로 보는 것이 적절합니다. 정확한 금액은 기능을 나눈 뒤 고정 견적으로 안내드리겠습니다.

가능하시면 현재 사용 중인 화면이나 개인정보를 제거한 Excel 예시를 보내주세요.

---

# 2. Excel / CSV 자동화

## 첫 응답 템플릿

안녕하세요. 반복되는 Excel/CSV 정리 작업을 자동화하는 형태로 진행할 수 있습니다.

정확한 범위를 위해 아래 4가지만 확인하면 됩니다.

1. 입력 파일 예시
2. 지금 사람이 직접 하고 있는 작업 순서
3. 한 파일의 최대 행 수
4. 최종 결과 파일 예시

예를 들어 다음 흐름을 브라우저 도구로 구현할 수 있습니다.

```text
파일 업로드
→ 오류 검증
→ 데이터 정리
→ 중복 제거 / 컬럼 매핑
→ 결과 확인
→ Excel/CSV 다운로드
```

공개 사례 `Customer Data Workbench V2.4`에서 실제로 Rule Builder, Validation Report, Column Mapping, Undo/Redo, Export를 확인할 수 있습니다.

단일 변환 작업은 **50만원 전후부터**, 검증/정리/리포트까지 묶인 업무 도구는 **150만원 이상 범위**를 기준으로 봅니다. 여러 양식, DB, 로그인, 관리자 기능이 추가되면 별도 산정합니다.

개인정보를 제거한 샘플 파일 1개만 있어도 1차 범위를 정리할 수 있습니다.

---

# 3. API / 기존 시스템 연동

## 첫 응답 템플릿

안녕하세요. 요청하신 내용은 기존 시스템과 외부 API 사이의 **데이터 연동 기능**으로 진행할 수 있습니다.

먼저 아래 정보를 확인하면 안정적으로 범위를 나눌 수 있습니다.

- Source 시스템 / Target 시스템
- API 문서 유무
- 인증 방식
- 어떤 데이터를 어느 방향으로 옮기는지
- 수동 실행인지, 주기 실행인지
- 실패 시 재시도 / 기록이 필요한지
- 기존 DB 저장 여부

단순 API 기능 1건은 **50만원 전후부터**, 데이터 변환·저장·오류 처리까지 포함하면 **150만원 이상**, 여러 연결과 실행 이력·중복 방지·운영 화면까지 필요하면 **300만원 이상**을 기준으로 검토합니다.

공개 `Integration Control Center V2`에는 Connection / Job / Run 모델, 실패 이력, 400/404/409 오류 계약, Idempotency-Key 중복 방지와 HTTP integration test가 구현되어 있습니다.

API 문서 또는 호출 예시가 있다면 민감정보를 제거한 뒤 공유해주세요.

# 견적을 바로 보내지 말고 질문이 필요한 경우

요청 내용이 너무 짧을 때는 금액부터 던지기보다 아래처럼 답합니다.

안녕하세요. 개발 가능 여부와 견적을 정확히 보려면 아래 4가지만 먼저 확인 부탁드립니다.

1. 현재 어떤 방식으로 처리하고 계신가요?
2. 가장 불편한 부분은 무엇인가요?
3. 개발 후 반드시 가능해야 하는 결과는 무엇인가요?
4. 기존 소스/DB가 있는 신규 개발인지, 기존 시스템 수정인지 알려주세요.

내용 확인 후 **필수 범위 / 선택 범위 / 예상 비용**으로 나눠서 답변드리겠습니다.

---

# 범위 초과 요청에 대한 답변

요청하신 기능은 구현 가능하지만 현재 견적 범위에는 포함되지 않은 항목입니다.

기존 완료 조건을 유지하면서 추가할 경우 일정과 테스트 범위가 함께 늘어나므로, 아래 두 방식 중 하나로 진행하는 것이 좋습니다.

- 기존 범위 완료 후 2차 개발로 분리
- 현재 범위에 추가하고 견적/일정을 재산정

기존 기능 품질을 떨어뜨리지 않기 위해 기능만 임의로 끼워 넣는 방식은 사용하지 않습니다.

---

# 예산이 부족한 고객에게 제안하는 축소 방식

전체 요구사항을 한 번에 구현하는 대신 다음처럼 1차 범위를 줄일 수 있습니다.

```text
1차: 핵심 입력 / 검색 / 상태처리
2차: 권한 / Excel / Audit
3차: 외부 API / Dashboard / 자동화
```

핵심 사용 흐름이 실제로 끝까지 동작하는 1차 버전을 먼저 만들고, 이후 운영하면서 우선순위가 높은 기능을 추가하는 방식입니다.

---

# 견적 후 확인 문구

견적에는 합의한 기능 범위, 제외 항목, 검수 기준을 함께 정리합니다.

개발 시작 전 최소한 아래 항목을 확정합니다.

- 구현 기능
- 제외 기능
- 입력 데이터
- 사용자/권한
- 상태 처리
- 외부 연동
- 완료 조건
- 납품 형태

이 기준이 확정되면 그 범위 안에서 일정과 금액을 고정하는 방식으로 진행합니다.
